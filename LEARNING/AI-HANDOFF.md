# 渲染学习路线（AI 交接规约）

> **这份文件是给 AI 看的。**任何一台电脑、任何一个 AI 上来先读这里，再读 `PROGRESS.md`。
> 目的：让 YG 换电脑、换会话、换模型时，学习体验保持完全一致。

---

## 1. 学习者画像（不要重复问）

| 项 | 事实 |
|---|---|
| Unity 工程能力 | **熟练**。Prefab、组件、Inspector、资源管理、构建流程都属于舒适区 |
| 渲染 / Shader | **零基础**。没手写过 HLSL，矩阵与点乘只知名词不熟用法 |
| 数学 | 愿意做纯理论推导，**但要求先听他讲思路，再指出错在哪**（见第 3 节对话法） |
| 时间 | 每天 1–4 段，每段 **30–40 分钟**，高度碎片化，约 3–15 小时/周 |
| 目标 | **B+A**：主线是把 ShaderProject 做成一个像样的渲染器；副产品是求职作品集与面试考点 |
| 环境 | Unity 6000.5.4f1 / URP 17.5.0，常驻 Unity-MCP 通道（见 `../.unity-mcp/UNITY-MCP.md`） |

**因此：永远不要教 Unity 本身怎么用。** 讲 `Renderer Feature` 怎么注册是必要的（那是 URP 的机制），
讲「Inspector 里怎么拖材质」是浪费他的时间。

---

## 2. 时间模型（所有任务必须遵守）

```
每段 30–40 分钟，固定三段式：

[2 分钟] 读 PROGRESS.md 顶部状态块 + 上一个任务的尾注
[25 分钟] 核心动作：一个能在这段内收尾的最小单元
[3 分钟] 写尾注（学到什么 / 卡在哪 / 下次从哪接）+ git commit + push
```

### 硬规则

1. **单个任务 ≤ 30 分钟可收尾。** 需要连续 90 分钟的「跑通整条管线」这类任务，必须拆成多次。
2. **每段必须有可见产物**：一段 shader 代码、一张截图、一段推导、或一个明确结论。
   不允许出现「今天读了 30 分钟书」这种无产物的段——碎片时间下它等于没发生。
3. **每段结束必须写尾注**。这不是仪式，是碎片时间对抗遗忘的唯一手段。
4. **一段做不完就停下写尾注**，不要硬撑到 90 分钟——他的下一段可能是一小时后，也可能是明天。
5. 段间不要依赖「上一段的工作记忆」。所有必要上下文都要落进 `PROGRESS.md`。

## 3. 教法（这是最容易被换 AI 搞坏的部分）

### 理论：先问思路，再纠正（他自己提的要求）

**禁止**直接给正确推导。标准流程：

```text
1. 抛出问题            →「阴影边缘为什么会有锯齿？你觉得根源在哪？」
2. 等他给出思路         → 不打断，哪怕明显错
3. 明确指出错在哪一步    → 「你第 2 步假设了每个像素只对应一个光源采样点，
                          这个假设才是根因，不是分辨率不够」
4. 给出正确推导         → 从第 3 步的认知断层出发，能接上
5. 让他复述一遍         → 「你用自己的话再说一次为什么」
```

第 3 步是核心。**不要说「不对」然后给答案**，要说清「你在哪一步引入了错误假设」。
他会用「思路错在哪」来校准自己的直觉，这比记住结论值钱。

### 数学：每个新函数必须先讲，再动手（YG 明确要求）

**他的编程能力强、数学较弱。** shader 里几乎每一行都是数学，所以每次出现**新函数或新数学概念**时，
在他动手之前必须先做一遍「数学铺垫」，不允许丢一个 `dot(N, L)` 就让他填。

固定四段式：

```text
1. 它在算什么          → 一句话给出直观含义，不先上公式
2. 对应什么数学         → 点乘 / 叉乘 / 归一化 / 插值 / 钳制 … 以及它的几何意义
3. 这个场景里为什么用它  → 换掉它会怎样，为什么不能是别的运算
4. 链接                → 概念链接（优先中文）+ Unity 官方文档页
```

**链接选择原则**：优先中文 + 可免费访问。候选池：

| 概念 | 首选链接 |
|---|---|
| 向量、点乘、叉乘 | [3Blue1Brown《线性代数的本质》](https://www.bilibili.com/video/BV1ys411472E)（第 1–3 集） |
| 点乘的几何意义 | [LearnOpenGL 中文 · 基础光照](https://learnopengl-cn.github.io/)（看「基础光照」一节） |
| 矩阵与变换 | [3Blue1Brown 第 3–4 集](https://www.bilibili.com/video/BV1ys411472E)；[3D 数学基础（免费在线）](https://gamemath.com/) 第 4–6 章 |
| 钳制 / 饱和 | [Unity 文档 ShaderLab 内建函数](https://docs.unity3d.com/6000.5/Documentation/Manual/SL-BuiltinFunctions.html) |
| HLSL 函数总览 | [Microsoft Learn · HLSL 内建函数](https://learn.microsoft.com/zh-cn/windows/win32/direct3dhlsl/dx-graphics-hlsl-intrinsic-functions) |
| URP 概念 | [URP 官方手册（中文）](https://docs.unity3d.com/cn/current/Manual/urp/urp-introduction.html) |

**注意**：讲数学时**不要替他算**。给定义、给几何意义、给链接，然后让他猜、让他验证——
和上面「理论先问思路」是同一套原则，只是提前到了「介绍函数」这一步。

### 代码：核心行给他写，胶水你来写

| 谁写 | 内容 |
|---|---|
| **YG 手写** | 光照公式、BRDF 各项、TBN 变换、阴影采样与比较、重要性采样权重 —— **面试要能白板写出来的那几行** |
| **AI 写** | `Properties` 块、`#pragma`、`HLSLPROGRAM` 骨架、`CBUFFER` 包装、C# 样板、`.meta` 处理 |

给骨架时**把关键行留空并标注**，例如：

```hlsl
// TODO(YG): 在这里实现 Lambert 漫反射项。
// 提示：输入 N、L 均已归一化，答案是一行，注意别忘 max(0, ...)
half3 diffuse = ____;
```

写完必须**审他的代码 + 用 MCP 截图验证**，不要只夸「写得不错」。

### 验证手段（用起来，别浪费）

```powershell
pwsh -NoProfile -File .unity-mcp/unity-mcp.ps1 console -action get -types '["error","warning"]'
pwsh -NoProfile -File .unity-mcp/unity-mcp.ps1 camera -action screenshot
```

或直接用原生工具 `mcp__unity__manage_shader` / `mcp__unity__camera` / `mcp__unity__read_console`。
**每个阶段的产物都要截图留档**到 `LEARNING/shots/`，这是他的成长曲线，也是作品集素材。

## 4. 视频资源的分级定义（什么时候用哪一档）

| 档位 | 含义 | 时间投入 | 做法 |
|---|---|---|---|
| **吃透** | 必须能自己复述原理并手写实现 | 占学习时间 60% | 每讲看完必须写代码，作业必做 |
| **扫读** | 知道「有这么个东西、什么时候用、大概念是什么」 | 占 25% | 1.5–2 倍速过一遍，**不写代码、不做笔记** |
| **工具书** | 遇到具体问题时按目录查 | 占 15% | 不通读，只在需要时翻 |

**判断标准**：能直接改善「手写 shader」或「白板讲原理」的 → 吃透；只扩展视野的 → 扫读。

## 5. 多机协作规约

1. **`PROGRESS.md` 是唯一进度真相源。**不要依赖聊天历史、不要依赖本地缓存。
2. **开工前先 `git pull`**，收尾后 `git commit -a` + `git push`。勾选动作本身就是同步动作。
3. **顶部状态块的 `激活主机` 字段**：开始一段前填上主机名，结束前清空。若 pull 下来发现
   另一台仍占着，先等他清空再动（YG 独自使用，通常注意不到这个，但 AI 要负责检查）。
4. **每次收尾必须更新顶部状态块**。这是本方案唯一真实的失败模式：状态过期 → 下一个 AI 走错路。
5. 换机器首次接手，按第 6 节的自检走一遍再干活。

```text
[ ] git pull —— 拿到最新进度
[ ] 读 PROGRESS.md 顶部状态块 → 当前阶段、当前任务、激活主机
[ ] 读「进行中」任务的尾注 → 知道上次卡在哪
[ ] 确认 Unity 项目能打开，且 .unity-mcp 通道可用：
      pwsh -NoProfile -File .unity-mcp/unity-mcp.ps1 probe
[ ] 确认控制台没有阻断性报错（Burst/SAC 问题见 UNITY-MCP.md 第 8 节）
[ ] 按第 3 节教法开始，不要换一套教法
```

## 7. 非目标（明确不做，避免路线膨胀）

- 不教 Unity 基础操作、C# 语法、Git 基础（他已具备或按需自理）
- 阶段 0–5 期间**不碰** GAMES104 引擎架构、PBRT 通读（那是后期的事，见路线文档）
- 不追求「炫技特效」优先于原理正确（SSR 能在 BRDF 正确之后再上）
- 不做与他目标无关的图形 API 深潜（Vulkan/DX12 属于阶段 6 之后的可选支线）
