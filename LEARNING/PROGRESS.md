## 阶段 0 · 数学直觉（预计 5 个任务）

> 目标：看得懂几何含义，不求推导。**每个任务都必须落成一个能在编辑器里看到的效果。**

- [x] **T0.1** `[25min]` 第一个片元输出：常量颜色
      写 `Assets/Shaders/ShaderLearning/FlatColor.shader`（URP Unlit 结构），`frag` 里返回一个**常量**颜色。
      先写 `half3(0.6, 0.8, 0.0)`；再把三个分量分别改成 0 和 1，各截一张图。
      **产物**：一张纯色截图 + 一张分量对照图。
      **判据**：能说清两件事——(1) 颜色就是一个三维数值，分量的含义是什么；
      (2) 为什么这里**故意不碰 UV**：UV 描述的是「片元在表面的位置」，
      现在就引入会把「位置」和「颜色」两个概念混在一起。
      渐变色留给 T0.2 —— 那时用 `dot(N, L)` 才真正产生逐像素变化。

- [x] **T0.2** `[30min]` 点乘可视化 —— 渐变第一次出现
      接入世界空间法线 N 与主光方向 L，用 `dot(N, L)` 的输出当作灰度写到三个通道。
      **这是整条路线第一次出现「逐像素变化」**：T0.1 的颜色全表面相同，这里开始每个像素都不同。
      **产物**：球体上出现明暗渐变 + 一张 `abs(dot)` 的对照图（看背光侧）。
      **判据**：能解释三件事——(1) `dot` 结果 1 和 -1 分别对应球面的什么位置；
      (2) 为什么背光侧会得到负数，以及 clamp 到 0 之后画面变成什么；
      (3) 法线为什么要转到世界空间才能和光方向做点乘。

- [ ] **T0.3** `[30min]` 叉乘与切线空间
      用 `cross(N, float3(0,1,0))` 伪造一个切线 T，再用 `cross(N, T)` 得到副切线 B
      （与 URP 同序：`sgn * cross(normalWS, tangentWS)`，见 `reference/urp-shaders/LitForwardPass.hlsl.txt:95`）。
      可视化**一次只做一根轴**：把某根轴整体做 `x * 0.5 + 0.5` 编码后输出，T / B / N 各截一张图。
      **不要**把三根轴各取一个分量塞进三个通道——一条通道只能装 1 个数，而一个单位方向要 2 个数
      （球面上的两个角），那种图是示意的、读不出方向（2026-10-15 实测：会退化成一颗蓝球）。
      **产物**：三张方向图（T / B / N 各一张），可拼成一张对照图。
      **判据**：能说清「切线空间」是相对于什么建立的——基准是**表面**（每点自己的 N + 该点的 U/V 走向），
      **不是**贴图、世界或相机；贴图只决定 T 的**来源**（UV 展开烘进模型）。
      自检：把 `up` 换个方向或转动物体，图案必须跟着变。

- [ ] **T0.4** `[30min]` 矩阵直觉
      在 shader 里手写一个 3×3 旋转矩阵并 `mul()` 应用到法线上，与 Transform 面板里
      手动旋转的直观结果对照。
      **产物**：旋转前后的对比截图。
      **判据**：能用一句话解释 `mul(M, v)` 和 `mul(v, M)` 的差别，以及为什么图形学常选其一。

- [ ] **T0.5** `[30min]` 阶段小结
      用三段话（不看资料）写下：向量是什么、点乘和叉乘分别在解决什么问题、矩阵变换解决了什么。
      **产物**：`LEARNING/notes/stage0-summary.md`。
      **判据**：AI 检查是否出现概念性错误，有错就当场重讲，不留到下阶段。

## 阶段 1 · 光栅化与 Shader 基础（预计 6 个任务）

> 这是整条路线性价比最高的一段。**每个 shader 的光照公式行必须 YG 自己写。**

- [ ] **T1.1** `[30min]` 读懂管线骨架
      逐行读懂 URP Unlit 模板：`Properties` → `SubShader` → `Pass` → `#pragma` → `Varyings` → `frag`。
      AI 负责画一张「顶点数据如何变成屏幕像素」的流程图。
      **产物**：流程图 + 你能不看注释复述每个 `#pragma` 的作用。

- [ ] **T1.2** `[30min]` 手写纯色与网格
      从零写一个 shader（不复制模板），输出棋盘格 `frac(uv * n)`。
      **产物**：棋盘格截图。
      **判据**：能解释为什么棋盘格会出现摩尔纹（这是下一阶段 MSAA 的伏笔）。

- [ ] **T1.3** `[35min]` 手写 Lambert 漫反射 ← **核心**
      YG 手写朗伯项：由 `_WorldSpaceLightPos0` 取 L，用 `UNITY_MATRIX_M` 变换 N。
      AI 只给骨架与 `#include` 部分。
      **产物**：正确的球体漫反射截图。
      **判据**：能白板写出这一行，并解释 `max(0, dot(N,L))` 里的 `max` 为什么不能省。

- [ ] **T1.4** `[35min]` Blinn-Phong 高光 ← **核心**
      YG 手写高光项：`H = normalize(L + V)`，`pow(max(0, dot(N,H)), _Shininess)`。
      **产物**：带高光球的截图，并手动拉高光参数看变化。
      **判据**：能解释 Blinn-Phong 相对 Phong 改了什么、为什么更快。

- [ ] **T1.5** `[35min]` 法线贴图与 TBN ← **核心**
      采样 `_NormalMap`，解包，用 TBN 变换到世界空间后接入光照。
      **产物**：同一球体，开/关法线贴图的对比截图。
      **判据**：能解释 `UnpackNormal` 之后为什么必须做 TBN 变换，而不是直接用。

- [ ] **T1.6** `[40min]` CPU 光栅化器 v1（分两次完成，第一次做三角形填充）
      用 C# 写一个 `Rasterizer.cs`：把三角形按重心坐标填充到一个 `Texture2D`。
      **产物**：编辑器里能看到自己画的三角形。
      **判据**：能说出重心坐标的三个权重之和为什么是 1。第二次（T1.7）再加 Z-Buffer。

- [ ] **T1.7** `[35min]` CPU 光栅化器 v2：Z-Buffer
      加入深度缓冲，让两个三角形正确遮挡。
      **产物**：正确遮挡的截图。
      **判据**：能说出 GPU 里 Z-Test 和 Z-Write 的顺序，以及为什么 Early-Z 能省算力。
